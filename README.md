# Meridian

Weekly demand forecasting, promotion uplift and price elasticity for Nordfalk
Dagligvarer A/S (client code `NFK`, engagement `NFK-2021-DEM`).

Meridian produces, every Tuesday morning:

* a 13 week forward forecast at store x article x week grain;
* a replenishment hand-off file in the `NFK-IF-014` interface format;
* the accuracy pack the commercial team take to the weekly trading meeting;
* price and promotion scenarios for the category managers.

## Layout

```
conf/            Kedro configuration (base + local)
data/            Local data layers, 01_raw only is committed
dbt/             nfk_analytics warehouse project, builds the marts
docs/            Architecture decisions and onboarding notes
notebooks/       Exploratory work, kept for traceability
src/meridian/    Pipelines, nodes, custom datasets, hooks
app/             Streamlit review app
tests/
tools/           One-off scripts (extract samplers etc.)
```

## Setup

The engagement laptop image ships Python 3.8.10. Nothing here is supported on
3.9 or later (the pinned pyarrow wheel does not build).

```
conda env create -f environment.yml
conda activate nfk-meridian
pip install -r requirements-dev.txt --index-url https://artifacts.internal/simple
pip install -e src
```

The internal index is needed for `nfk-kedro-operator`, which is not on PyPI.
If you are off the VPN, drop the `--index-url` and install the operator by
hand from the wheel in the engagement share.

Credentials: copy `conf/local/credentials.yml.template` to
`conf/local/credentials.yml` and fill in the warehouse user. Nothing in
`conf/local` is committed.

## Running

```
make de          # raw -> intermediate -> primary
make features    # primary -> feature table
make train       # feature table -> demand model + elasticity model
make evaluate    # accuracy pack
make score       # 13 week forecast + NFK-IF-014 export
make app         # Streamlit review app on localhost:8501
```

`kedro run` with no arguments runs the training path (de -> fe -> train ->
eval). The scoring run is scheduled separately as `NFK_MERIDIAN_SCORE_W`.

## Data

Raw extracts land on the client SFTP as `NF_*.csv`: semicolon separated,
latin-1, comma decimals, dates as DD/MM/YYYY. `NordfalkCSVDataSet` absorbs
the dialect; do not read them with plain `pandas.read_csv`.

The warehouse marts (`mart_sales_weekly`, `mart_store_week_traffic`,
`mart_promo_performance`) are built by the dbt project in `dbt/` and mirrored
to `data/01_raw/marts/` for local runs. See `dbt/README.md`.

A small synthetic sample of every extract is committed under `data/01_raw/`
so the pipelines can be run without warehouse access. It is generated by
`tools/make_sample_extract.py` and is not client data.

## Conventions

* Store ids are four digits; the first two are the region. `9xxx` are depots
  and `xx99` is the HQ test store, both out of scope.
* Fiscal year N starts on the first Monday of October of year N-1, 4-4-5
  periods (`src/meridian/utils/fiscal_calendar.py`).
* Line values on the extract carry 25% VAT and the container deposit. Both
  come off in `data_engineering` before anything is modelled.
* Reporting is in DKK; the group view converts at the fixed engagement rate
  in `conf/base/globals.yml`.
